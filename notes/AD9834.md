# AD9834 DDS — Field Notes

MCLK on TC1: **75 MHz** (BOM correct, schematic had 50 MHz — corrected).

SPI interface: SCLK idles high, data latched on falling edge, MSB first, 16-bit words, write-only (no MISO).
notFSYNC (active low) frames each 16-bit transfer individually.

The AD9834 datasheet describes this as CPOL=0, CPHA=1 — which is **opposite** to the Arduino/standard convention. In Arduino terms this is **SPI_MODE2** (CPOL=1, CPHA=0). Use `SPI_MODE2` in `SPISettings`.

## Register addressing (DB15:DB14)

| DB15 | DB14 | Target |
|------|------|--------|
| 0 | 0 | Control register |
| 0 | 1 | FREQ0 |
| 1 | 0 | FREQ1 |
| 1 | 1 | PHASE (DB13 selects PHASE0/PHASE1) |

## Control register (DB15:DB14 = 00)

| Bit | Name | Description |
|-----|------|-------------|
| DB13 | B28 | 1 = 28-bit frequency write (two consecutive 16-bit words, LSB first then MSB). 0 = 14-bit half-word mode (use HLB to select half) |
| DB12 | HLB | When B28=0: 1 = write MSBs, 0 = write LSBs. Ignored when B28=1 |
| DB11 | FSEL | 0 = use FREQ0, 1 = use FREQ1 in phase accumulator |
| DB10 | PSEL | 0 = use PHASE0, 1 = use PHASE1 |
| DB9 | PIN/SW | 0 = software control (use control bits), 1 = hardware pin control |
| DB8 | RESET | 1 = reset internal registers → DAC output at midscale |
| DB7 | SLEEP1 | 1 = disable MCLK |
| DB6 | SLEEP12 | 1 = power down DAC |
| DB5 | OPBITEN | 1 = **enable SIGN BIT OUT pin**. Must be 0 if MODE=1. Pin is high-Z when 0 |
| DB4 | SIGN/PIB | 1 = comparator output on SIGN BIT OUT, 0 = MSB (or MSB/2) of DAC data |
| DB3 | DIV2 | When SIGN/PIB=0: 1 = MSB direct, 0 = MSB/2 |
| DB2 | — | Reserved, always 0 |
| DB1 | MODE | 0 = sine (SIN ROM active), 1 = triangle (SIN ROM bypassed). Must be 0 if OPBITEN=1 |
| DB0 | — | Reserved, always 0 |

Useful control word constants:

| Value | Effect |
|-------|--------|
| `0x2100` | B28=1, RESET=1 — reset device |
| `0x2000` | B28=1, FSEL=0, sine output, SIGN BIT OUT disabled |
| `0x2800` | B28=1, FSEL=1, sine output, SIGN BIT OUT disabled |
| `0x2028` | B28=1, FSEL=0, sine + SIGN BIT OUT enabled (comparator, DIV2=1) |

## Frequency registers

With B28=1 (28-bit mode), write two consecutive words to the same register address:
1. First word: `reg_addr | (freq_word & 0x3FFF)` — 14 LSBs
2. Second word: `reg_addr | ((freq_word >> 14) & 0x3FFF)` — 14 MSBs

Frequency word: `freq_word = round(f_out / f_MCLK * 2^28)`

Example for 1 MHz with 75 MHz MCLK: `freq_word = 3,579,139`

## SIGN BIT OUT (SIGNOUT) pin

**SIGNOUT is high-impedance at power-up** (OPBITEN=0 default). Any signal seen on it before config is parasitic coupling on the floating pin — not a real output.

To enable: set OPBITEN=1 in control register. MODE must be 0.

SIGN/PIB=1, DIV2=1 gives a comparator-derived square wave — useful as a quick proof-of-life check at the DDS output frequency.

## FS_ADJUST pin

Analog input setting full-scale DAC output current:
`I_OUT_FS = 18 × V_FSADJ / R_ADJUST`

Datasheet default: 6.8 kΩ from FS_ADJUST to AGND.
On TC1: driven by Teensy PWM (pin 6) through an on-board low-pass filter. Disconnect or float FS_ADJUST only temporarily for debugging; the full-scale current is undefined when floating.

## Startup sequence

1. Assert RESET: send `0x2100`
2. Write frequency register (two words for 28-bit mode)
3. Write phase register if needed (default 0 is fine)
4. Deassert RESET and configure output: e.g. `0x2028` (sine, SIGNOUT enabled via comparator)

## TC1 wiring (Teensy 4.1 → board header)

| Board pin | Teensy pin | Function |
|-----------|------------|----------|
| SDATA | 11 | MOSI |
| SCLK | 13 | SCK |
| notFSYNC | 10 | CS (active low) |
| RESET | 9 | GPIO — **must be driven LOW (OUTPUT) before initialising DDS** |
| FS_ADJUST | 6 | PWM output |

## Known issues / lessons learned

- **RESET pin must be driven LOW before initialising the DDS.** A floating RESET pin held the chip in reset throughout TC1 bringup — all SPI writes were ignored, SIGNOUT was silent. Root cause: the AD9834 constructor was also being called at global scope (before Arduino `setup()`), meaning SPI was not yet initialised. Fix: construct the DDS object inside `setup()`, and drive RESET LOW explicitly before doing so.
- SIGNOUT must be broken out on the next board revision — essential for proof-of-life since the AD9834 has no readback (SPI is write-only).
- **SIGNOUT is high-Z at power-up** (OPBITEN=0). Any signal seen before config is parasitic coupling on the floating pin. Silence after config means OPBITEN was never written — check SPI first.
- The library's `update_freq_reg` ends with control word `0x38` (OPBITEN=1, SIGN/PIB=1, DIV2=1, B28=0, FSEL=0). This enables SIGNOUT as a comparator output (useful for debugging) but leaves B28=0 after each call.
- The AD9834 uses a non-standard CPOL/CPHA labelling (CPOL=0, CPHA=1 in their docs = Arduino SPI_MODE2). Don't set the SPI mode from the datasheet labels directly.
- Digital supply current: ~13 mA idle, ~17 mA when DDS is active and outputting.
